# 铃声 & 消息通知 — 技术开发设计方案

> 视角：高级开发工程师（Senior Developer）。基于产品方案 v3.4（`铃声与消息通知-设计方案.md`）与现有 `main.js` / `config.js` / `preload.js` / `src/*` 代码现状，产出可落地的技术实现方案。
> 配套：`mockup-settings.html`、`mockup-notification-center.html`、`mockup-tray-menu.html`（视觉稿，开发对齐）。
> 状态：**v2（已根据"桌面代理为网页提醒中继、用户数据由网页端推送"约束修订）**，确认后进入实现。

## 1. 现有架构盘点（开发前必读）

| 维度 | 现状 | 对本次改造的影响 |
|---|---|---|
| 进程模型 | 单主进程 + 多 `BrowserWindow`（call/meeting/toast 预创建或按需） | 沿用单主进程；新增 settings / notification-center 两个常驻窗口 |
| 消息弹窗 | `showToast`→`displayToast` 每次 `new BrowserWindow`+`loadFile`+`did-finish-load` 后才 IPC 渲染 | **白框根因**。改为单窗口常驻预加载，永不重建 |
| 铃声 | `getRingtonePath()` 永远返回 `assets/ringtone.m4a` 单一文件 | 重写为 `resolveRingtone(callType, callerId)` 场景/联系人解析 |
| 已连接用户 | `connectedClients` Map（ws→{userId,userName,...,connected}）已维护 | 托盘"已连接用户"直接复用，无需新协议（除非要"连接新用户"入口） |
| IPC 桥 | `preload.js` 暴露 `electronAPI`（call/meeting/toast） | 新增 settings / notification-center 两套桥 |
| 音频自动播放 | `makeWebPrefs()` 已设 `autoplayPolicy:'no-user-gesture-required'` | 通知中心 `<audio>` 可无手势播放，无需改 |
| 打包 | `asar:true`，`asarUnpack:["assets/**/*"]` | 内置铃声落在 `assets/`（解包）；用户上传铃声落 `userData`（asar 外） |
| 自启 | 托盘菜单已实现 `app.setLoginItemSettings({openAtLogin})` | 设置面板复用同一 API，双向同步 |
| 单实例 | `requestSingleInstanceLock()` 已就位 | 设置窗口单例可复用同一思路 |
| 角色定位 | 桌面通知代理是**网页提醒的"强提醒中继"**：网页经 WS 把提醒推过来，桌面端转成 OS 级弹窗/铃声/系统卡 | 架构主线：web → WS → main.js → 强提醒；桌面端不生产业务数据 |
| 数据归属 | 网页端已能下发 `senderId/Name/Avatar`、`caller*`、`conversationId`；`KICKED_OUT` 由 TUIChatEngine 在 `StatusIndicator.vue`/`ConferenceOverlay.vue` 触发 | **除铃声等本地偏好外，用户数据由网页推送**，桌面端不手工录入联系人 |
| 联系人标识 | 网页 `contacts.ts` 的 `imUserId` = TUIChatEngine `userID` = `mobile_account`；`layout.vue` 下发 `senderId=userProfile.userID`、`callerId` 同为 IM userID | 联系人铃声 key 统一为 **IM userID**，跨端一致 |
| 网页桥接 | `web/src/utils/desktop-notifier.ts` 已封装 `initNotifier/showCall/showMessage/...` 并经 HTTP 握手+WS 连接 | 新增能力（SYNC_CONTACTS、url、KICKED/NET）在此 SDK 扩展，desktop-notifier 同步处理 |

**关键结论**：本次是**存量改造**而非重写。最大改动是"消息弹窗从按需建窗 → 常驻预加载窗口"，以及"铃声从单文件 → 场景/联系人解析 + 本地上传"。通话/会议窗口的铃声播放机制（预加载 + `<audio>`）可直接复用，只需把传入的 `ringtonePath` 换成解析结果。

## 1.5 数据归属边界（本方案核心约束）

桌面通知代理**不生产业务数据**，只把网页推送的提醒做强呈现。明确划分：

### 由网页端经 WS 推送（桌面端只读/缓存）
| 数据 | 来源 | 说明 |
|---|---|---|
| 联系人列表 | 网页 `contacts.ts`（后台 `getCallParticipants`），经新增 `SYNC_CONTACTS` 推送 | 含 `id(imUserId)` / `name` / `avatar`；桌面端仅缓存用于"联系人专属设置"列表 |
| 消息字段 | `SHOW_MESSAGE_NOTIFICATION`：`conversationId` / `senderId`(IM userID) / `senderName` / `senderAvatar` / `content` / **`url`(新增)** | 通知中心直接使用，桌面端不解析/不补全 |
| 来电字段 | `SHOW_CALL_NOTIFICATION`：`callerId`(IM userID) / `callerName` / `callerAvatar` / `callType` | 同上 |
| 被踢下线 | 网页 `StatusIndicator.vue` 监听 `TUIChatEngine.KICKED_OUT` → 推送 `KICKED` | 网页权威，桌面端不自行探测 |
| 网络离线/恢复 | 网页 IM 连接状态（`useIMConnection` / `StatusIndicator`）→ 推送 `NET_OFFLINE` / `NET_ONLINE` | 网页权威；桌面端可选保留极简兜底 |

### 桌面端本地（settings.json + userData，不依赖网页）
| 数据 | 说明 |
|---|---|
| 通知模式 `notifyMode` | normal / silent / blockChat / dnd（用户本地偏好） |
| 开机启动 `autoStart` | 本地客户端行为 |
| 铃声总开关 `ringtoneEnabled` + 每场景 `ringtones` | 本地偏好 |
| 联系人铃声关联 `contactRingtones` | **只存"联系人id → 铃声文件"映射**，联系人元数据来自网页 |
| 上传铃声 `userData/ringtones/` + `localRingtones` | 唯一允许落本地的"用户数据"（产品明确铃声例外） |
| 消息设置 `messageNotify` | 显示方式/时长，本地偏好 |

> **联系人标识契约（跨项目必须一致）**：所有联系人 key = **TUIChatEngine `userID`** = `mobile_account` = 网页 `contacts.ts.imUserId` = 消息/来电 payload 的 `senderId`/`callerId`。`SYNC_CONTACTS` 携带的 `id` 必须与此相同，否则联系人专属铃声无法命中。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│ main.js (主进程)                                              │
│  ├─ settingsStore        settings.json 读写 + 默认值合并       │
│  ├─ ringtoneResolver     resolveRingtone(callType,callerId)    │
│  ├─ notificationCenter   常驻窗口控制器 + unreadMap + sysAlerts │
│  ├─ trayMenu             右键菜单（已连接用户 + 设置 + 自启）    │
│  ├─ wsServer / httpServer 现有，新增 KICKED/NET_* 消息处理      │
│  └─ 现有 call/meeting 窗口（铃声接入 resolveRingtone）         │
└───────────────┬───────────────────────┬───────────────────────┘
                │ IPC                    │ IPC
   ┌────────────▼──────────┐   ┌─────────▼──────────────────────┐
   │ settings-window.html  │   │ notification-center.html        │
   │ (单例, 左侧导航+内容) │   │ (单例常驻, 预加载, 按会话聚合)    │
   │ 通用/铃声/消息/联系人 │   │ 会话卡 + 系统通知卡 + 自己的audio │
   └───────────────────────┘   └─────────────────────────────────┘
```

窗口生命周期策略（根除白框的核心）：
- **settings / notification-center 在 `app.whenReady` 时创建并 `loadFile`，`show:false` 常驻**，与 call/meeting 窗口一致。
- 数据通过 IPC 实时下发，窗口**永不因消息而销毁/重建**。
- 通知中心默认隐藏；有未读/系统通知时 `show()`，空闲 `duration` 秒（或手动）`hide()`。
- 为避免显示瞬间的空白，窗口 `backgroundColor` 设为卡片底色（白），HTML `body` 不透明；由于已预加载，展示时内容早已绘制完成。

## 4. 数据层

### 4.1 `userData/settings.json`（schema，与产品方案一致）
```jsonc
{
  "autoStart": true,
  "notifyMode": "normal",            // normal | silent | blockChat | dnd
  "ringtoneEnabled": true,           // 总开关（响铃/静音）
  "ringtones": {
    "call_audio": { "enabled": true,  "file": "default" },
    "call_video": { "enabled": true,  "file": "default" },
    "meeting":    { "enabled": true,  "file": "default" },
    "message":    { "enabled": true,  "file": "default" }
  },
  "contactRingtones": {
    "u_10086": { "message": "ringtones/x1.mp3", "voice": "default" }
  },
  "localRingtones": [ "ringtones/x1.mp3" ],   // 自动维护的本地候选项
  "messageNotify": { "display": "content", "duration": 8 }
}

// 联系人元数据缓存（来自网页 SYNC_CONTACTS，桌面端不手工录入；仅用于"联系人专属设置"列出可选项）
// 注意：此数组只缓存展示信息，铃声关联在上方 contactRingtones；key 必须 = IM userID
"contactsCache": [
  { "id": "u_10086", "name": "张总", "avatar": "https://.../userInfo/u_10086.png" }
]
```

### 4.2 `settingsStore.js` 行为
- 启动时 `load()`：读取 `path.join(app.getPath('userData'),'settings.json')`；不存在则用 `DEFAULTS` 创建；存在则**深合并默认值**（容忍旧版本缺字段）。
- `get()` / `set(partial)`：`set` 做浅合并后防抖（~300ms）写盘，避免频繁 IO。
- 提供 `getMerged()` 给 `resolveRingtone` 与通知中心读取当前生效配置。
- 路径常量：`USER_DATA = app.getPath('userData')`、`RINGTONE_DIR = USER_DATA/ringtones`、`SETTINGS_PATH = USER_DATA/settings.json`。

### 4.3 铃声落盘（无大小限制）
- 上传走**主进程原生文件框**：设置页调用 `electronAPI.pickRingtone()` → 主进程 `dialog.showOpenDialog({filters:[{name:'音频',extensions:['mp3','m4a','wav']}]})` → 取绝对路径 → `fs.copyFile` 到 `RINGTONE_DIR/<hash>.<ext>`（`hash=sha1(原路径+大小+时间)` 防重名）。
- **为何用 fs.copyFile 而非 IPC 传 buffer**：产品要求"不限制大小"，大文件走 IPC ArrayBuffer 易触发上限/内存压力。主进程直接 copy 最稳。
- 回写：把相对路径 `ringtones/<hash>.<ext>` 推入 `localRingtones`，返回 `{path, name}` 给前端，候选项即时出现并选中。
- `"default"` 哨兵：指向 `assets/ringtone.m4a`（随包，已 asarUnpack），**不落盘**。

### 4.4 内置铃声预设（`config.js` 新增）
```js
ringtonePresets: {
  default:   'assets/ringtone.m4a',   // 系统默认（所有场景回退）
  call_audio:[ 'assets/ringtone.m4a' ],
  call_video:[ 'assets/ringtone.m4a' ],
  meeting:   [ 'assets/ringtone3.m4a' ],
  message:   [ 'assets/ringtone2.m4a' ]
},
// 候选项展示名（与文件解耦，便于改名）
ringtoneNames: {
  'assets/ringtone.m4a':'经典铃声',
  'assets/ringtone2.m4a':'消息提示音',
  'assets/ringtone3.m4a':'会议铃音',
  'assets/ringtone4.m4a':'清脆叮咚'
}
```
- 解析文件路径统一用 `path.join(__dirname, rel)` → `file:///` 绝对路径（与现有 `getRingtonePath` 一致）。

## 5. 模块设计

### 5.1 `ringtoneResolver.js`
```js
// 返回 file:// 绝对路径 或 null（不播放）
function resolveRingtone(s, callType, callerId) {
  const st = settingsStore.getMerged();
  if (st.notifyMode === 'dnd') return null;            // 全屏蔽
  if (!st.ringtoneEnabled) return null;                // 总开关静音
  if (st.notifyMode === 'silent') return null;         // 静音模式

  const sceneKey = { audio:'call_audio', video:'call_video', meeting:'meeting', message:'message' }[callType];
  if (callType === 'message' && st.notifyMode === 'blockChat') return null;  // 屏蔽聊天消息

  // 联系人专属：语音类合并 audio/video/meeting
  if (callerId && st.contactRingtones[callerId]) {
    const key = callType === 'message' ? 'message' : 'voice';
    const v = st.contactRingtones[callerId][key];
    if (v != null) return v === 'default' ? toFile(st.ringtonePresets.default) : toFile(v);
  }
  if (!st.ringtones[sceneKey].enabled) return null;    // 该场景开关关
  const v = st.ringtones[sceneKey].file || 'default';
  return v === 'default' ? toFile(st.ringtonePresets.default) : toFile(v);
}
```
- `toFile(rel)`：`rel` 以 `assets/` 开头 → `path.join(__dirname, rel)`；以 `ringtones/` 开头 → `path.join(USER_DATA, rel)`；统一返回 `file:///` 绝对路径。

### 5.2 `notificationCenter.js`（主进程控制器）
状态：
```js
const unreadMap = new Map();   // conversationId -> {conversationId,name,avatar,last,count,time,url,senderId}
const sysAlerts = [];          // {id,type:'kick'|'offline',sticky,data}
let ncWindow = null;
```
方法：
- `preCreate()`：创建窗口（`makePopupWindowOpts` 变体，右下角定位，`show:false`），`loadFile(notification-center.html)`，完成后 `nc-init` 下发 `{settings, unread: [...unreadMap.values()], sysAlerts}`。
- `pushMessage(payload)`：
  - 校验 `payload.conversationId` 必填（否则用 `senderId` 兜底）。
  - 更新 `unreadMap`（累加 count、刷新 last/time）。
  - 解析铃声：`const rp = resolveRingtone('message', payload.senderId)`（可能为 null）。
  - 若 `notifyMode==='blockChat'||'dnd'`：**不展示窗口**、不响铃，仅 `updateUnreadCount(+1)`（托盘红点）。
  - 否则：`ncWindow.webContents.send('nc-unread-update', {...})`；`show()`；播放 `rp`（通过 `nc-play` IPC 或窗口内 `<audio>` 设 src 播放）；启动 `duration` 自动收起计时。
- `markRead(conversationId|'all')`：从 `unreadMap` 删除/`updateUnreadCount` 重算；`send('nc-unread-update')`。
- `pushSysAlert(alert)` / `dismissSysAlert(id)`：维护 `sysAlerts` 并 `send('nc-sysalert'|'nc-sysalert-dismiss')`。
- 自动收起：每次有新消息重置空闲计时；`duration` 秒无交互 → `hide()`（未读保留在托盘）。
- `syncContacts(list)`：**接收网页 `SYNC_CONTACTS`**，写入 `userData/contactsCache.json`（与 `settings.json` 同目录）。仅当某联系人尚无比铃声关联时保留；已删除联系人不清空其 `contactRingtones`（避免误删用户设置），但列表中不再展示。通知中心/设置窗口读取此缓存列出"联系人专属设置"候选。
- **消息字段直接使用推送值**：`pushMessage` 直接采用 `payload.senderName/senderAvatar/content/url`，桌面端不做本地解析/补全（用户数据由网页权威）。

### 5.3 `trayMenu`（修改 `updateTrayMenu`）
- 在已连接用户区之后、自启之前插入：`{ label:'⚙ 设置', click: ()=>openSettingsWindow() }`。
- `openSettingsWindow()`：设置窗口单例——已存在则 `focus()`，否则创建并 `show()`。
- 自启 checkbox 与设置面板 `autoStart` 双向同步（开关任一处都写 settingsStore + `app.setLoginItemSettings`）。
- "连接新用户"入口（产品稿有）：本期可选，建议 deferred（已连接用户已由 WS REGISTER 自动维护）。

## 6. IPC 契约表

### 6.1 主进程 → 渲染进程
| 通道 | 发往 | 载荷 | 说明 |
|---|---|---|---|
| `nc-init` | center | `{settings, unread[], sysAlerts[]}` | 预加载完成首帧 |
| `nc-unread-update` | center | `{unread[]}` 或单条 `{item}` | 增量/全量刷新聚合列表 |
| `nc-sysalert` | center | `{id,type,data}` | 新增/更新系统卡 |
| `nc-sysalert-dismiss` | center | `{id}` | 移除系统卡 |
| `nc-settings-changed` | center | `{settings}` | 实时响应 display/duration 变化 |
| `nc-play` | center | `{path}` | 播放消息铃声（path 可为 null） |
| `settings-data` | settings | `{settings, localRingtones, presets}` | 打开时下发当前配置 |
| `settings-saved` | settings | `{settings}` | 保存回执（可选） |

### 6.2 渲染进程 → 主进程（via `electronAPI`）
| 方法 | 发往 | 载荷 | 说明 |
|---|---|---|---|
| `ncOpenConversation(id,url)` | main | `{conversationId, url}` | 打开会话（main `open-browser` 或 `shell.openExternal`） |
| `ncMarkRead(id\|'all')` | main | — | 清未读 |
| `ncReconnect()` | main | — | 被踢"重新登录" |
| `ncClose()` | main | — | 收起窗口 |
| `settingsLoad()` (invoke) | main | — | 返回 settings |
| `settingsSave(partial)` | main | `{...}` | 局部保存 |
| `pickRingtone()` (invoke) | main | — | 返回 `{path,name}`（主进程文件框+copy） |
| `setAutoStart(bool)` | main | — | 写 settings + `setLoginItemSettings` |

- 主进程侧用 `ipcMain.handle` 处理 `settingsLoad`/`pickRingtone`（需返回值），其余用 `ipcMain.on`。
- `preload.js` 新增对应 `onXxx`/`sendXxx` 暴露。

### 6.3 新增 WS 消息（网页 → 桌面代理，扩展 `desktop-notifier.ts`）
| 类型 | 载荷 | 桌面端处理 |
|---|---|---|
| `SYNC_CONTACTS` | `{ contacts:[{id,name,avatar}] }` | `notificationCenter.syncContacts()` 写 `contactsCache`；刷新设置窗口联系人列表 |
| `SHOW_MESSAGE_NOTIFICATION`（补 `url`） | 原字段 + `url`（会话打开地址） | `pushMessage` 用 `url` 打开会话 |
| `KICKED` | `{ device, reason, time }` | `pushSysAlert({type:'kick',sticky:true})` |
| `NET_OFFLINE` | `{ time }` | `pushSysAlert({type:'offline'})`（无声） |
| `NET_ONLINE` | `{ time }` | 将 offline 卡转"已恢复"，3s 后 dismiss |

> 网页侧 `desktop-notifier.ts` 需新增 `syncContacts()` / `notifyKicked()` / `notifyNetOffline()` / `notifyNetOnline()` 并接入 `layout.vue` / `StatusIndicator.vue` / `useIMConnection`。

## 7. 关键流程

### 7.1 启动
`app.whenReady` → `preCreateCallWindow()` / `preCreateMeetingWindow()`（现有） / **`preCreateNotificationCenter()`** / **`preCreateSettingsWindow()`(隐藏)** → 其余不变。

### 7.2 收到聊天消息（`SHOW_MESSAGE_NOTIFICATION`）
```
handleBrowserMessage(SHOW_MESSAGE_NOTIFICATION)
  └─ 校验 conversationId（补 conversationId 到 payload 协议）
  └─ notificationCenter.pushMessage(payload)
       ├─ 更新 unreadMap
       ├─ resolveRingtone('message', senderId)
       ├─ blockChat/dnd → 仅 updateUnreadCount，不弹
       └─ 否则 nc-unread-update + show + nc-play(path)
```
> **协议改动**：现有 payload 已有 `conversationId`/`senderId`(IM userID)/`senderName`/`senderAvatar`/`content`。需**补充** `url`（打开会话用，桌面端 `ncOpenConversation` 经 `shell.openExternal` 或浏览器 scheme 打开）。`senderId` 已可用于联系人铃声解析（无需改动）。

### 7.3 收到来电/会议（`SHOW_CALL_NOTIFICATION`）
```
showCallWindow(payload)
  └─ ringtonePath = resolveRingtone(payload.callType, payload.callerId)
  └─ send('call-data', {...payload, ringtonePath, ringtoneConfig})
```
- `callerId` 取自 payload（需网页侧在通话协议里带 callerId；若无则仅走场景默认）。
- 通话窗口 `startRingtone` 已支持"不同路径走慢路径加载"，无需改播放逻辑。

### 7.4 系统通知（事件由网页权威下发，桌面端不自行探测网络）
```
网页 StatusIndicator.vue(KICKED_OUT) → desktop-notifier.notifyKicked() → WS KICKED
  → notificationCenter.pushSysAlert({type:'kick', sticky:true, data:{device,time}, ringtone:'message'})
网页 useIMConnection/StatusIndicator(IM 断连) → notifyNetOffline() → WS NET_OFFLINE
  → pushSysAlert({type:'offline'})
网页(IM 重连) → notifyNetOnline() → WS NET_ONLINE
  → 将 offline 卡转"已恢复"，3s 后 dismissSysAlert
```
- 被踢复用"消息通知"场景铃声（`resolveRingtone('message',null)`，受总开关/场景开关约束）。
- 离线卡**无声**（不调用 nc-play）。
- 系统卡不计入 `unreadMap`、不调 `updateUnreadCount`。
- 桌面端**不再**做网络层探测兜底（保持架构单一数据源）；若后续需要，可加极简 `online` 事件监听仅在网页未连接时辅助，默认不启用。

## 9. 打包与平台约束

- **asar**：`asar:true` + `asarUnpack:["assets/**/*"]` 不变。新内置铃声放 `assets/` 即被解包为真实文件，`resolveRingtone` 用 `path.join(__dirname,...)` 取真实路径。
- **用户数据**：`settings.json` 与 `ringtones/` 落在 `app.getPath('userData')`（asar 外真实文件系统），读写安全；**切记不要**尝试写入 `__dirname`（asar 只读）。
- **macOS**：自启 `setLoginItemSettings` 跨平台可用；`LSUIElement:true` 已隐藏 Dock，符合纯托盘应用。
- **Windows**：`requestedExecutionLevel:"asInvoker"`（无需管理员）即可写 `userData` 与注册自启项；自启通过 `setLoginItemSettings({openAtLogin:true})` 写入启动目录/注册表。
- **无大小限制上传**：`fs.copyFile` 不受 IPC buffer 限制，跨平台一致。
