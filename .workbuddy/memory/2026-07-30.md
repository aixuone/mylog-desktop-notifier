# 2026-07-30 工作日志

## 屏幕共享：contextIsolation 导致 preload shim 无效（决定性修复）
- 现象：诊断窗 R6 已 PASS（音视频/纯视频 getDisplayMedia 均成功），但腾讯会议室仍「屏幕共享过程中发生未知错误，请重试」。用户始终拿不到 `[MainPage Media]` 日志。
- 根因：`makeWebPrefs()` 开 `contextIsolation:true`，preload 运行在隔离 world，对 `navigator.mediaDevices.getUserMedia` 的包裹渗透不到网页 main world；腾讯 TRTC SDK 在 main world 调 getUserMedia（legacy `chromeMediaSource:'desktop'` 路径），完全绕过 preload shim，且拿不到 `chromeMediaSourceId` → 捕获失败。
- 修复：
  - 新增 `src/screenshare-shim.js`：纯浏览器 main-world 脚本，包裹 getUserMedia/getDisplayMedia，检测 `chromeMediaSource:'desktop'/'screen'` 且无 `chromeMediaSourceId` 时注入主进程预置的首选屏幕源 id；埋点经 `window.electronAPI.logMedia`。
  - `main.js` 新增 `injectScreenShareShim(win)`：`desktopCapturer` 枚举首选 `screen:` 源 → 经 `executeJavaScript` 预置 `window.__SCREEN_SHARE_CFG__` → 再 `executeJavaScript(shim)` 注入 main world；在 `openMainPage` 的 `mainPageWindow` 的 `did-finish-load` 调用。
  - `preload.js`：删除无效隔离-world shim，仅保留 `logMedia` 通道暴露给 `electronAPI`。
- 验证：`node --check` 三文件（main.js / preload.js / screenshare-shim.js）均通过。`get-desktop-source` IPC handler 现已不再被 shim 使用（源改由 cfg 预置），保留无害。
- 下一步：重新出包，让客户在会议室发起屏幕共享，主进程应打印 `[ScreenShare] shim injected to main world` + `[MainPage Media] [main-world-shim] getUserMedia ...`；若仍 ERR，日志会给出具体 name/message。记忆 MEMORY.md 坑位① P2 已同步修正（preload shim 无效 → 必须 executeJavaScript 注入 main world），防止未来回退。

## 屏幕共享第四轮：DevTools 日志分析 + chrome.desktopCapture 根因
- 用户打开 DevTools（Ctrl+Shift+I），截取主页面窗口初始化日志：
  - Agora RTC_AMBULANCE 检测到 `navigator.mediaDevices.getUserMedia` 为"非原生代码"（即我们的 shim）
  - **但 `getDisplayMedia` 不在 Agora 非原生列表中** → Agora 只 patch getUserMedia
  - **TRTC/TUICallEngine v3.5.9 从未调 getDisplayMedia 或 getUserMedia({chromeMediaSource:'desktop'})** → SDK 屏共享调用根本没出现
  - **`[ScreenShare]` handler 也从未收到请求** → 确认 SDK 未调 getDisplayMedia
- **根因锁定**：TRTC 在 Electron 环境下**优先检查 `chrome.desktopCapture.chooseDesktopMedia` 是否存在**。找不到 → 认定屏共享不可用 → 直接报错不调任何 API。这正是腾讯官方 TRTC Electron 集成（`trtc-electron-sdk`）提供 `chrome.desktopCapture` 的原因。但由于 `contextIsolation:true`，preload 的 chrome 对象渗透不到 main world → 对 SDK 不可见。
- 修复：在 `screenshare-shim.js`（main world 脚本）增加 `chrome.desktopCapture.chooseDesktopMedia` mock + `cancelChooseDesktopMedia` mock。`chooseDesktopMedia` 回调直接返回主进程预置的首选屏幕源 id（`SOURCE_ID`）。同源 iframe 也注入。三层保险：A（chrome.desktopCapture mock 让 TRTC 检测到"扩展可用"）B（getUserMedia 兜底注入 chromeMediaSourceId）C（getDisplayMedia 埋点）。
- `node --check screenshare-shim.js` 通过。MEMORY.md 坑位① P2 已更新为 chrome.desktopCapture 根因。

## 屏幕共享第三轮：添加渲染进程 console 桥接 + DevTools 入口
- 用户反馈：无法查看主页面窗口内部 console 日志（TRTC SDK 的报错/调用路径全在渲染进程里），也没地方看日志。
- 问题核心：之前所有 shim 日志都靠 `electronAPI.logMedia` 手动上报，只能看到 shim 拦截到的调用；SDK 内部的 console.log/warn/error 完全不可见——如果 SDK 在调用 API 前就内部报错退出，shim 根本拦截不到。
- 修复：
  - `main.js`：在 `mainPageWindow` 创建后添加 `webContents.on('console-message')`，把渲染进程所有 console 输出（log/warn/error）桥接到主进程控制台，前缀 `[MainPage Console]`。用户在 `npm run dev` 终端就能看到 SDK 内部日志。
  - `main.js`：注册 `CommandOrControl+Shift+I` 全局快捷键，直接 toggle DevTools（`webContents.toggleDevTools()`）。
  - `main.js`：托盘右键菜单新增「调试窗口」项（`webContents.openDevTools()`），让用户也能从菜单打开 DevTools。
  - `main.js`：require 列表新增 `globalShortcut`；`mainPageWindow.on('closed')` 时注销快捷键。
  - 窗口关闭=隐藏时不再注销（复用窗口场景）；仅窗口真正销毁（`closed` 事件）才注销。
- `node --check main.js` 通过。
- 下一步：用户 `npm run dev` 后：①在终端看到 `[MainPage Console]` 渲染日志 ②用 Ctrl+Shift+I 或托盘「调试窗口」打开 DevTools ③在会议室点击屏幕共享 ④把完整日志（含渲染进程 console）发来。

## 屏幕共享第五轮：shim 日志双通道 + getter 拦截
- 问题：用户在 DevTools 里看不到任何 `[main-world-shim]` 消息——shim 的 `log()` 只走 IPC 到主进程，不写 DevTools console。需要同时看 shim 消息和 TRTC SDK 内部日志才能定位。
- 改进：
  - `screenshare-shim.js` 的 `log()` 函数改为双通道：先 `console.log('[main-world-shim] ' + msg)`（DevTools 可见），再 IPC 到主进程。两处都能看到 shim 消息。
  - 在 `chrome.desktopCapture` 和 `chrome.desktopCapture.chooseDesktopMedia` 上加 getter 拦截：当 TRTC SDK 读取这些属性时，自动打印 `chrome.desktopCapture READ (#N)` / `chooseDesktopMedia READ (#N)`。这是**终极定位手段**——能精确检测 SDK 是否检查了 `chrome.desktopCapture`，以及是在什么时候检查的（初始化时 vs 点击屏共享时）。
  - iframe 也加 getter 拦截。
- `node --check` 通过。
- 下一步：用户 `npm run dev` → 进入会议室 → 点击屏幕共享 → DevTools console 里应该能看到 `[main-world-shim]` 消息 + getter 拦截日志（如果 TRTC 真的读了 `chrome.desktopCapture`），否则会看到 TRTC 检查了什么别的属性。
