# 2026-09-09

## Mac Intel 无法安装 —— 根因与修复
- 现象：用户反馈 Mac Intel 装不上（"无法安装/已损坏/架构不兼容"）。
- 根因：`package.json` 的 `build.mac.artifactName` 原为 `"${productName} 安装包 ${version}.${ext}"`（**无 `${arch}`**），而 `mac.target` 同时打 `x64` + `arm64`。一次 `--mac` 产出两个同名 DMG，后构建的 arm64 覆盖 x64，最终分发的只有一个 **arm64** DMG。arm64 App 在 Intel Mac 上无法运行（Rosetta 仅 x86_64→arm64，反向不可）。
- 修复：mac.artifactName 改为 `"${productName} 安装包 ${version}-${arch}.${ext}"`，两个架构产物各占文件名 → 分别产出 `…-x64.dmg`（Intel）与 `…-arm64.dmg`（Apple Silicon）。
- 验证：`node -e require('./package.json')` 解析 OK，mac.artifactName 已含 `${arch}`。
- 旁注（非阻塞）：entitlements.mac.plist 已含 `device.camera`/`device.audio-input`（Hardened Runtime 媒体访问前提），无问题；Electron 32 要求 macOS 10.15+，过老的 Intel Mac（10.14 及以下）即便 x64 也无法启动。
