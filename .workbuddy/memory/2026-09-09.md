# 2026-09-09

## Mac Intel 无法安装 —— 根因与修复
- 现象：用户反馈 Mac Intel 装不上（"无法安装/已损坏/架构不兼容"）。
- 根因：`package.json` 的 `build.mac.artifactName` 原为 `"${productName} 安装包 ${version}.${ext}"`（**无 `${arch}`**），而 `mac.target` 同时打 `x64` + `arm64`。一次 `--mac` 产出两个同名 DMG，后构建的 arm64 覆盖 x64，最终分发的只有一个 **arm64** DMG。arm64 App 在 Intel Mac 上无法运行（Rosetta 仅 x86_64→arm64，反向不可）。
- 修复：mac.artifactName 改为 `"${productName} 安装包 ${version}-${arch}.${ext}"`，两个架构产物各占文件名 → 分别产出 `…-x64.dmg`（Intel）与 `…-arm64.dmg`（Apple Silicon）。
- 验证：`node -e require('./package.json')` 解析 OK，mac.artifactName 已含 `${arch}`。
- 旁注（非阻塞）：entitlements.mac.plist 已含 `device.camera`/`device.audio-input`（Hardened Runtime 媒体访问前提），无问题；Electron 32 要求 macOS 10.15+，过老的 Intel Mac（10.14 及以下）即便 x64 也无法启动。

## macOS 麦克风/摄像头不可用排查（Windows 可用、macOS 不可用）
- 结论：代码逻辑没问题。`main.js` 的 `setPermissionRequestHandler`(643) + `setPermissionCheckHandler`(659) 对可信来源已放行 media/display-capture，Windows 能跑靠同一套逻辑。macOS 失败是环境/构建层问题。
- 最可能根因（ranked）：① 在 Mac 上跑 dev 模式(`electron .`)——裸 Electron 二进制无 UsageDescription 字符串/entitlements，TCC 直接拒；② 出包但签名/公证没真正生效（ad-hoc 签名新版 macOS 拒相机/麦克风）；③ 测的是旧包（字符串是后加的补丁）；④ TCC 在该机已是拒绝/未登记态，需 `tccutil reset`；⑤ **屏幕共享**另需 `NSScreenCaptureUsageDescription`（之前整项目缺失）+ 系统"屏幕录制"列表授权 + **授权后必须重启 app**。
- 已修复：`package.json` mac.extendInfo 补 `NSScreenCaptureUsageDescription`（屏幕会议共享 macOS 硬缺口）。重新 `--mac` 出包才进 Info.plist。
- 验证命令（Mac 上跑）：`defaults read ".../Info.plist" NSCameraUsageDescription` / `codesign -d --entitlements -` / `codesign -dvvv ... | grep Authority` / `sudo tccutil reset Camera com.tianyuan.mylog.desktop-notifier`。
