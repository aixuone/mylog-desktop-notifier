## 测试反馈修复（第4轮）：呼叫铃声不响

### 根因（两个叠加 bug）
1. **`toFile` 路径拼错（主因）**：`lib/ringtoneResolver.js` 的 `toFile()` 对 `assets/` 前缀做了 `rel.replace(/^assets\//,'')` 再拼 `assetsDir`(= `__dirname`)，结果拼成 `__dirname/ringtone.m4a`（缺 assets 目录，文件不存在）。默认设置 `ringtones.call_audio.file='default'` → `resolve('audio')` 必走 `toFile('assets/ringtone.m4a')` 返回这个不存在的路径；又因该返回值非空，`showCallWindow` 里的 `rp = resolve(...) || getRingtonePath()` 兜底不触发。
   - 修复：去掉 `.replace(/^assets\//,'')`，改为 `path.join(assetsDir, rel)` → `__dirname/assets/ringtone.m4a`（已验证文件存在）。
2. **`crossOrigin='anonymous'` 阻断 file:// 媒体**：`src/call-window.html`、`src/meeting-window.html` 给 `audio` 元素设了 `crossOrigin='anonymous'`，本地 `file://` 资源在 CORS 模式下校验失败、永不触发 `canplaythrough`。本地铃声无需 CORS，删掉 4 处。

## 测试反馈修复（第5轮）：被踢/离线通知常驻

### 需求
被踢下线与离线通知需**持续显示**（与聊天消息不同，聊天消息按 duration 自动隐藏），在"重连上线"或"用户点击"时才隐藏。

### 根因
`notificationCenter.js` 的 `resetIdle()` 无论有无常驻通知都会在 duration 秒后隐藏整个窗口；`markRead` 在清空未读时也会隐藏窗口——导致 `kick`(虽标 sticky) 与 `offline`(sticky:false) 通知都被自动收起。

### 修复
1. 新增 `hasStickyAlert()` 判断是否有常驻系统通知。
2. `resetIdle()`：有常驻通知时不挂自动隐藏定时器，窗口保持显示。
3. `NET_OFFLINE` 改为 `sticky: true`（与 kick 一致，两者均为常驻）。
4. `dismissSysAlert()`：移除后重新评估可见性——仍有时长驻则保持；否则有未读则恢复常规自动隐藏计时，无未读则隐藏窗口。
5. `markRead()`：有常驻通知时不清空窗口（避免"全部已读"关掉常驻通知）。
6. 网页端/HTML：点击被踢卡片的"重新登录"按钮，除 `api.reconnect()` 外也 `dismissSysAlert(id)`（满足"用户点击可隐藏"）。

### 隐藏触发矩阵
- 离线：收到 `NET_ONLINE` → `dismissSysAlert('offline')`（已有）；或点"关闭"。
- 被踢：点"重新登录"(reconnect+dismiss) 或点"知道了"(dismiss)。
- 两者均不会因 duration 超时自动消失。

### 改动文件
桌面端：main.js、lib/notificationCenter.js、src/notification-center.html

### 校验
node --check 通过；notification-center.html 内联脚本语法 OK。

## 未读数实时同步（第6轮）：桌面未读数 > 网页真实未读

### 根因
桌面端 `pushMessage` 用 `count += 1` **累加模型**；网页端 `conversationList` 的 watcher 在同一次消息到达时可能多次触发 `showMessage`，且桌面端从未拿到会话的**权威 `unreadCount`**（IM SDK 真实值）。叠加后桌面显示数持续膨胀、远大于网页真实未读。另外网页侧已读/归零状态只通过显式 `MARK_READ` 同步，"网页里读掉"桌面端不会更新。

### 修复（让网页端 IM SDK 成为唯一真相源）
1. **网页端 desktop-notifier.ts**：新增 `syncUnread(items)` 发送 `SYNC_UNREAD`（items 仅含未读>0 会话，已读/归零由"不在列表"表达）。
2. **网页端 layout.vue**：
   - 引入 `syncUnread`；新增 `syncDesktopUnread(list)` 过滤"自己给自己发的 C2C"并映射出 `{conversationId,name,avatar,count,last,url,senderId}`（群聊优先 `groupProfile`）。
   - 在 `conversationList` watcher 中**每次变化都先 `syncDesktopUnread(newList)`**（实时权威同步，含归零/已读）；保留 `showMessage` 仅用于新消息弹窗+响铃，并在 payload 中带 `unreadCount`。
   - `onConnectionChange(true)` 时补推一次当前权威未读（修正离线期间偏差）。
3. **桌面端 lib/notificationCenter.js**：
   - 新增 `syncUnread(items)`：以权威数据**重建** unreadMap（仅 count>0 入表；快照比对，仅"确有新增未读"时弹窗，避免列表刷新闪烁）；清空后若无未读且无常驻系统通知则隐藏窗口。
   - `pushMessage`：`unreadCount` 若由网页下发则**以该权威值为准**（不再 +1），未下发时回退旧累加逻辑。
   - 导出 `syncUnread`。
4. **桌面端 main.js**：新增 `case 'SYNC_UNREAD'` 调用 `notificationCenter.syncUnread(msg.payload.items)`。

### 效果
- 弹窗总未读 + 各会话未读角标 = 网页 IM SDK 真实未读数，不再偏大。
- 网页里读掉/自动已读 → 会话列表变化 → 桌面端同步清零。
- 重连桌面代理后自动补推当前权威未读。

## 测试反馈修复（第7轮）：消息弹窗一闪即逝 + 联系人删除失败

### 问题1：消息通知弹窗一闪就没了（未尊重"消息提醒持续时长"）
- **根因**：`syncUnread()` 旧逻辑用 `unreadMap.clear()` 整表清空重建。网页端对同一条新消息会**同时**下发 `SHOW_MESSAGE_NOTIFICATION`(pushMessage 已入表) 与 `SYNC_UNREAD`；当 `SYNC_UNREAD` 竞态地以"空/未含新会话"到达时，syncUnread 把刚加入的会话清空 → `unreadMap.size===0` → 立刻 `win.hide()`，表现为"显示即隐藏"。且旧逻辑仅"确有新增未读"才 `showWindow`，普通刷新不续期计时。
- **修复（lib/notificationCenter.js）**：
  1. 新增 `hiddenByUser` 标志 + `GRACE_MS=2500` 竞态保护。
  2. `syncUnread` 改为**增量合并**而非清空重建：以权威 items 更新/新增；移除网页已读(不在 items)的会话，但 **2.5s 内刚由 pushMessage 加入的会话保留**（防止竞态误删）。
  3. 新消息续期：`pushMessage → showWindow() → resetIdle()` 每次重置为完整 duration；`syncUnread` 对"由 sync 自身产生的新未读"才 `showWindow`，否则仅 `resetIdle()`（续期、保持当前可见性）。满足"新消息来重新计算时长（继续延长）"。
  4. `resetIdle()` 增加 `|| hiddenByUser` 守卫；`showWindow()` 开头 `hiddenByUser=false`。
  5. `nc-close` / `markRead(清空)` / `dismissSysAlert(无未读)` 时置 `hiddenByUser=true` 并隐藏——用户主动关闭后，普通 sync 刷新不再把窗口弹出来，直到下条新消息到达(pushMessage 重置标记)。

### 问题2：联系人专属设置中删除已添加联系人失败，关闭面板后重复出现
- **根因**：`settingsStore.set()` 用 `deepMerge` 合并；旧删除逻辑 `api.settingsSave({ contactRingtones: Object.assign({}, S.contactRingtones) })` 是**合并**而非替换，被删 key 会被 deepMerge 保留；磁盘 `settings.json` 始终留着该联系人，关闭面板重读即重现。
- **修复**：
  1. `lib/settingsStore.js` 新增 `removeContactRingtone(cid)`（显式 `delete` + `scheduleSave`），并加入 exports。
  2. `src/preload.js` 暴露 `removeContactRingtone(cid)` → `ipcRenderer.send('settings-remove-contact', cid)`。
  3. `main.js` 新增 `ipcMain.on('settings-remove-contact', ...)` 调用 `removeContactRingtone`。
  4. `src/settings-window.html` 删除按钮改为 `delete S.contactRingtones[cid]; api.removeContactRingtone(cid)`（真正落盘删除）。
