## 下载体验改造（用户第二轮反馈：下载=打开浏览器 → 下载列表）

**背景**：网页内 `<a>` 下载链接上一轮被 `setWindowOpenHandler` 拦截后直接 `shell.openExternal` 弹浏览器，体验差。用户建议在菜单栏右上方加下载列表，支持打开文件/目录。

**实现（3 文件）**：
1. **main.js**：
   - 新增全局 `downloads` 数组 + `downloadSeq`；`handleWillDownload()` 命名函数（落盘用户下载目录、同名加序号 (1)/(2)、记录进度/状态），用 `global.__dlSessionBound` 防重复注册（openMainPage 重建窗口时会重复执行）。
   - `setWindowOpenHandler` 增加 `DOWNLOAD_EXT_RE` 扩展名白名单（zip/rar/pdf/xlsx/mp3/mp4/apk 等 40+ 类）→ `looksLikeDownload()` 命中则 `downloadURL` 直接下载（进下载中心），普通外链仍 `openExternal`。

   - 新增 IPC：`downloads:list / open / open-folder / cancel / clear`；`openDownloadsWindow()` 无边框 400×480 置顶小窗，锚定主页面窗口右上角（菜单栏下方）。
2. **src/preload.js**：新增 `downloadsList / downloadsOpen / downloadsOpenFolder / downloadsCancel / downloadsClear / onDownloadsChanged`。
3. **src/downloads-window.html**（新建）：无边框面板，拖拽标题栏 + 关闭；任务卡片（文件名/徽标/大小/进度条）；操作按钮「打开文件」「所在目录」「取消」；底部「清空已完成」；`downloads-changed` 实时订阅。

**验证**：main.js / preload.js `node --check` 通过；downloads-window.html 内联脚本 `new Function` 通过。未打包实跑。

## 标题栏架构修正：同窗叠加 → 独立悬浮窗口（用户指出网页补位问题）
用户问"不能让网页自动填充菜单的高度吗"——点破同窗叠加方案死穴：网页是远程页面，全屏隐藏标题栏后无法自己补位。
**架构决策：标题栏 = 独立 BrowserWindow 悬浮窗**，浮在网页主窗口顶部。网页主窗口始终全屏，全屏切换只 hide()/show() 标题栏小窗 → 网页 100% 自动填充，零改动。
- 小窗属性：frame:false + skipTaskbar:true + focusable:false + resizable:false，尺寸=主窗宽×38px，锚定主窗口 bounds 左上角。
- 全屏：enter-html-full-screen / enter-full-screen → hide()；leave-* → show()+setPosition。
- 非全屏：主窗 move/resize 跟随 setBounds 同步。
- 项目先例：下载中心/通知中心已是独立悬浮窗模式。设计稿 v2 第 6 章已重写。

## 标题栏一体化修复（用户反馈：悬浮窗与主窗不像一体 + 主窗带系统标题栏）
**根因**：主窗口仍是 `frame:true`，系统默认标题栏（约 30px）与自绘标题栏（38px）叠成两条，必然不像一体。
**修复**：
1. **主窗口 `frame:false`** + `resizable:true` + `autoHideMenuBar:true`——去掉系统标题栏。
2. **原生菜单栏全部移除**：6 处 `setMenu(buildWindowMenu())` → `setMenu(null)`（在线用户/设置/刷新/下载功能迁至标题栏 ⋮ 菜单/头像菜单）。
3. **标题栏窗口 = 主窗口子窗口**（`setParentWindow(mainPageWindow)`）：自动跟随主窗口移动/最小化/关闭，视觉一体。
