## 日历首次打开宽度变 0 修复
- **现象**：桌面端首次冷打开，日历页 `.fc-scrollgrid` 列宽恒为 0（内容挤成一条）。
- **根因**：FullCalendar 在容器宽度为 0 的时刻完成首次测量并缓存。首次冷打开时序特殊：主窗口 splash→`loadURL(remote)` 切换，且自绘标题栏 CSS 经 `did-finish-load` 后 `insertCSS`+`executeJavaScript` 异步注入（`backgroundThrottling:false`+慢加载加剧），日历挂载瞬间布局未稳；原 `onMounted` 只 `render()` 不 `updateSize()`，`onActivated` 的双 rAF `updateSize` 时序不够稳。
- **修复（web 侧 `src/components/calendar/index.vue`）**：
  - `.cal-body` 加 `ref="calBodyRef"`。
  - 新增 `resizeCalendar(extraDelay)`（立即 + 双 rAF + 可选延时兜底）与 `setupCalResizeObserver()`（`ResizeObserver` 监听 `.cal-body`，任何 0/隐藏→真实尺寸变化自动 `updateSize()`，顺带兜住标题栏 CSS 注入导致的 `.main-layout` 高度变化）。
  - `onMounted` 调 `resizeCalendar(300)` + `nextTick(setupCalResizeObserver)`；`onActivated` 复用 `resizeCalendar(60)`；`onBeforeUnmount` 调 `teardownCalResize()`。
- **验证**：`npx vue-tsc --noEmit` 仅 baseUrl 弃用告警（Exit 0）。实际 0 宽消除需桌面端首次冷启动确认。

## 删除上传铃声（含引用清理与防误删）
- **影响面**：①一个铃声可能被 4 场景 + N 联系人（message/voice）同时引用，只删文件不清理引用 → 播放静音失败；②物理文件在 `userData/ringtones/`；③渲染层本地缓存 S/C 需重拉。
- **实现**：
  - `lib/settingsStore.js`：新增 `removeLocalRingtone(rel)`——localRingtones 移除 + ringtoneNames 清理 + 场景引用回退默认（message→`assets/ringtones/default.mp3`，其余→`default`）+ 联系人引用移除字段（空对象整体删 cid）。deepMerge 无法删 key，必须显式 delete。
  - `main.js`：`ringtone-delete` IPC——rel 必须 `ringtones/` 前缀 + basename join 防路径穿越；`removeLocalRingtone` → `fs.unlinkSync`（ENOENT 忽略）→ `notifySettingsChanged()` → 返回最新 {names, localRingtones, urls}。
  - `src/preload.js`：暴露 `ringtoneDelete(rel)`。
  - `src/ringtone-picker.js`：「我的铃声」行加 🗑 删除按钮；新增 `confirmDialog`（复用 .rn-* 体系，红色危险按钮，Enter/Esc/遮罩）；删除流程=停试听→二次确认→onDelete→成功后 closeModal（重开即新列表）。
  - `src/settings-window.html`：新增 `onDelete()`——IPC 删除成功后 `settingsLoad` 重拉 S/C 并 `renderRingtone()+renderContacts()` 重建选择器（关键：不重拉 S 则界面仍显示已删铃声）。
- **验证**：`node --check` 5 文件全过；**单元测试**（mock electron）验证引用清理：多场景+多联系人引用同一铃声删除后全部正确回退/移除、未引用项不受影响、空联系人设置整体删除——ALL PASSED。
