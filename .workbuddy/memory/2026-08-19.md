# 2026-08-19 桌面-网页 通话协调（铃声去重 + 接听置顶）

## 需求
1. 桌面被叫弹窗点「接听」→ 直接打开网页窗口并置顶；「拒绝」不变。
2. 桌面端已连接时，网页停止播放被叫铃声（语音/视频/会议），由桌面端播放，消除双响。

## 根因分析
- 网页被叫铃声来源：音频/视频通话 = **TUICallKit 自带来电铃声**（`enableMuteMode` 唯一作用域）；会议 = `alertService.startRingtoneLoop`（CUSTOM 模式），已在 `handleMeetingReceived` 用 `if (!isAgentAvailable())` 门控。
- 旧逻辑：`startCallAlert`（音频/视频）里的 `startRingtoneLoop` 早已注释掉，网页自身不播音频；但 TUICallKit 自带来电铃声**不受 `isAgentAvailable()` 门控** → 音频/视频必然与桌面双响。会议因 `startMeetingAlert` 已门控，连接时仅桌面响（理论不双响，连接竞态除外）。

## 改动
- `desktop-notifier/main.js`：新增 `focusMainPage()`（强制 show+focus+短暂 `setAlwaysOnTop(true)` 1.2s 后还原），规避 `openMainPage()` 对"已可见且聚焦"窗口执行隐藏的切换语义（接听场景会误隐藏）；在 `ipcMain.on('call-action')` / `('meeting-action')` 的 `action==='accept'` 分支调用。拒绝/超时不变。
- `web/src/components/layout.vue`：`setCallsEvents()` 初始化后调用 `TUICallKitAPI.enableMuteMode(isAgentAvailable())`；在已有 `onConnectionChange` 处理器内 `try{ TUICallKitAPI.enableMuteMode(online) }catch` 实时切换——桌面在线→关 TUICallKit 来电铃音，离线→恢复。`enableMuteMode` 仅影响来电铃音，**不影响主叫等待音**（等待音由 web `startWaitingAlert` 自管）。

## 校验
- 桌面 `node --check main.js` 通过。
- 网页改 `layout.vue`：`TUICallKitAPI: TUICallService` 类型含 `enableMuteMode(enable:boolean): Promise<void>`（calls-uikit-vue d.ts 确认），类型合法；SFC 未跑全量 vue-tsc，发版前建议 `npm run build` 复验。
- 会议网页铃声已门控，无需改动。

## 生效
- 桌面改动需**重启 Electron** 主进程。
- 网页改动需重新构建/热更（Vite dev 即时）。

# 2026-08-19（续）桌面端打开网页"空白"排查

## 现象
用户反馈：桌面端打开网页（主页面窗口）错误/显示空白。

## 排查结论
- 桌面端加载链健康：`openMainPage()` splash→`loadURL(远程主页)`；`preload.js`（contextIsolation+electronAPI 桥）语法 OK；`makeWebPrefs()` 配置正常；远程主页 `https://data.tygps.com/mylog-pc/` curl 返回 200 + 正常 SPA 壳（Vue v2.7.19.4，CSP 仅 upgrade-insecure-requests）；兜底错误页 `src/mainpage-error.html` 纯本地无远程依赖（加载失败必显示"无法打开主页"卡片，不会空白）。
- 用 Playwright headless 加载生产主页（未登录）：**无 pageerror / 无 console.error / 无失败请求，`#app` 有 2889 字符内容** → 入口全局渲染正常，白屏不在全局层。
- 本轮回合 `layout.vue` 两处 `enableMuteMode` 改动均已 `try/catch` 包裹（loginIM 路径 + onConnectionChange 路径），且未登录时不触发，排除其直接责任。
- 推论：白屏发生在**登录后**渲染路径（与登录态相关的组件），桌面端加载链无法自愈；需网页端 F12 Console 报错定位。

## 桌面端加固（main.js openMainPage）
- 新增 `mainLoadTimer`（20s 加载超时兜底）：远程主页 20s 内未完成（`did-stop-loading` 未触发）→ 强制 `loadURL(mainpage-error.html?reason=timeout)`，避免"卡死/超慢→永久空白"。
- 新增 `webContents.on('render-process-gone')`：渲染进程崩溃 → 显示错误页（reason=crash），替代空白。
- `did-fail-load` 加防递归（错误页自身失败不再二次 load）。
- `node --check main.js` 通过；临时诊断文件 test-load.js / probe-web.js / electron-debug*.log 已清理。

## 待用户确认（定位 web 端白屏必需）
- 现象细分：卡在蓝色转圈 splash？纯灰/白底？还是"无法打开主页"错误卡？
- 按 `Ctrl+Shift+I` 在网页窗口内打开 DevTools → Console 红色报错（尤其含 `.vue` 的堆栈）截图/粘贴。
- 沙箱环境无法渲染 Chromium（无 GUI），本地 GUI 实测不可行；生产主页需登录态，Playwright 未登录无法复现登录后白屏。

# 2026-08-19（再续）白屏根因定位 + 修复（用户给 Console 日志）

## 根因（日志 data.tygps.com-1787129043154.log 实证）
- 桌面端实际加载的主页是 **`http://data.tygps.com/mylog-pc-test/`**（用户配置主页地址为 http，测试环境 mylog-pc-test）。
- 该 HTML 内 JS/CSS 引用**绝对 `https://`** 地址（如 assets/index-*.js、vue-vendor-*.js、tencent-im-*.{js,css}）。
- `http://`（origin）加载 `https://` 子资源，因 scheme 不同被浏览器判**跨源 → CORS 拦截**（`No 'Access-Control-Allow-Origin' header`），所有 JS/CSS `net::ERR_FAILED` → SPA 初始脚本全失败 → 白屏。
- 连带 AgoraRTC 报 `WEB_SECURITY_RESTRICT: Your context is limited by web security, please try using https protocol`（`enumerateDevices() not supported`）。
- 结论：**不是网页 SPA 运行时 bug，而是桌面端以 http 非安全上下文加载导致混合内容被拦截**。网页端文件本身正常（Playwright 未登录加载生产主页 `#app` 有 2889 字符无报错）。

## 修复（main.js openMainPage）
- 读取 `mainPageUrl` 后做规范化：http:// **强制升级 https://**（localhost/127.0.0.1/::1 例外，保留 http 安全上下文）；原 http 地址留存为 `fallbackUrl`。
- splash→`loadURL` 改用 https 版 `url`。
- `did-fail-load` 新增回退分支：若失败的是 https 且存在 `fallbackUrl`（http），则回退加载 http（仅一次，`fallbackUrl=null` 防二次回退），否则走错误页（防递归保留）。
- 升级动机：网页被叫/音视频通话依赖 WebRTC（需安全上下文），且同源策略要求页面与子资源同 scheme，http 页加载 https 子资源必被 CORS 拦。
- `node --check main.js` 通过。

## 生效
- **重启 Electron** 主进程即生效：用户配置的 http 主页会自动以 https 加载，白屏消除。
- 可选：用户也可在「设置-关于」把主页地址手动改为 `https://` 开头（自动升级后非必须）。
- 验证预期：加载 `https://data.tygps.com/mylog-pc-test/` → 子资源同 origin → CORS 不再拦截 → 正常渲染；AgoraRTC 安全上下文恢复。
